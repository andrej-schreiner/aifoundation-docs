This page collects everything the docs are built from, in the real page frame. Switch between light and dark with the theme menu in the header, and check each section in both.

The page is a draft: it appears in `bun run dev` and never in a production build. It is also kept out of search.

It is organised in three libraries:

- **Style guides**: the visual, content and interaction standards, such as colours, type scale and spacing.
- **Component library**: the UI blocks, split into base elements and composite components.
- **Pattern library**: layout patterns for page shells, and task and flow patterns for what readers do on the site.

#### Aside

The short notes in guides (`:::note`, `:::tip`, `:::caution`, `:::danger`). Because guides use many of them, they are a lighter take on the inline notification, styled like the tags: a tinted background, the heading and the Telekom icon in the matching colour, the body in the normal text colour. Tokens: `aifs.aside.*`. For a notice that needs attention, use the Inline notification.

| In Markdown | Colour | Use for |

| `:::note` | Informational (blue) | Extra information that is useful but not essential |
| `:::tip` | Success (green) | A better or faster way to do something |
| `:::caution` | Warning (orange) | Something that can go wrong, such as a rate limit |
| `:::danger` | Danger (red) | Data loss, security risks or costs |

#### Table

Aligned with Scale's [Table](https://telekom.github.io/scale/?path=/docs/components-table--standard): a grey header row with bold small text and rounded top corners, no outer frame, a line under each row and a hover fill. Tokens: `aifs.table.*`. Every Markdown table and the three data tables (rate plans, model table, model comparison) use it without new markup.

- **Default** (16px cell padding): Markdown tables and the rate plans table.
- **Compact** (8px): dense data, as in the model table and the model comparison.
- **Sortable headers** get a fill on hover and press and a blue focus ring, as in Scale.
- Deviation from Scale: text in cells wraps, because docs tables hold descriptions.

<Showcase label="Default: a Markdown table" block>

| Parameter | Type | Description |

#### Tabs

Aligned with Scale's [Tab Navigation](https://telekom.github.io/scale/?path=/docs/components-tab-navigation--text-icon): a light line under the tabs, the selected tab in magenta with a 3px bar, hover and press a shade darker, 48px high. It is Starlight's `Tabs` component, restyled with tokens (`aifs.tabs.*`), so the arrow keys move between tabs and tabs with the same `syncKey` switch together across the page.

Use tabs for alternatives of the same content, such as one request in several languages. Don't use them for steps that follow each other.
