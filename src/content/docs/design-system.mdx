This page collects everything the docs are built from, in the real page frame. Switch between light and dark with the theme menu in the header, and check each section in both.

The page is a draft: it appears in `bun run dev` and never in a production build. It is also kept out of search.

It is organised in three libraries:

- **Style guides**: the visual, content and interaction standards, such as colours, type scale and spacing.
- **Component library**: the UI blocks, split into base elements and composite components.
- **Pattern library**: layout patterns for page shells, and task and flow patterns for what readers do on the site.

## Building with this system

The same rules apply to people and to AI coding tools; `AGENTS.md` in the repository root holds them for the tools, and `GAPS.md` lists every known difference from Scale.

- **Reuse first.** Use the components on this page with the props and values they have. The list is closed: a prop or variant that is not documented does not exist.
- **Tokens only.** Colours, spacing, radii and type come from `--aifs-*` tokens (`tokens/aifs.docs.tokens.json`, built with `bun run tokens`). No raw values; a missing value becomes a token first.
- **If nothing fits, write a GAP.** Note what is missing and the closest thing that exists, and ask, instead of inventing a part.
- **Something new follows Scale.** A new component mirrors [Scale's](https://telekom.github.io/scale/?path=/docs/scale-design-system--page) API and look with our tokens, has every state and meets WCAG 2.1 AA, and gets an entry on this page.
- **A difference is listed or it is a bug.** Every deliberate deviation gets a row in `GAPS.md`.

A button that confirms its own action, such as a copy button, puts the confirmation into the `success` slot. A script sets `data-state="success"` on the button and removes it after about 1.5 seconds. The slot then replaces the button's content, and ghost and secondary buttons turn the success colour (`aifs.button.success.text`); primary keeps its colours. The swap is only visual, so also announce the result in a live region and update `aria-label`.

`successTooltip` adds a tooltip that shows during the same state and says what happened, such as what was copied. It is the same tooltip as below (see Tooltip, `aifs.tooltip.*`). It sits above the button, centred (`tooltipPlacement="top"`) or with end edges aligned (`top-end`, for a button in a corner, as in the model card). It is hidden from screen readers, which hear the live region instead. It never grows wider than the nearest size container less `--aifs-tooltip-inset`, so a long text breaks instead of leaving the screen.

#### Card

Starlight's `LinkCard` and `Card` in one frame: the chrome surface, a subtle border and the card radius. Inside, top to bottom: icon, bold title, description in the muted text colour. Tokens: `aifs.card.*`.

- **Link card** points to another page. The whole card is the link; the arrow sits at the end, centred on the text. On hover and focus the border turns magenta and the arrow moves a little; keyboard focus adds the button's focus ring.
- **Card** only informs, so it has no hover. Its icon is drawn in the text colour.
- **Next steps** after a page's intro or its last section are link cards in a `link-card-row`, as in the home page's Integrations section: the link texts as card titles, a description only where one was written for the card (never a made-up one). The quickstart, Coding agent setup and the model pages use them in place of a "Next:" line of text links.
- **Previous and next links** at the end of every page (Starlight's pagination) are link cards too: "Previous" or "Next" in the description colour, the page title as the card title, the arrow at the outer edge, moving outward on hover. Starlight renders them; they are restyled in `redesign.css`. This page has none; see the end of [Authentication](/getting-started/authentication/).

Several cards go in a `CardGrid`: one column, then two equal columns from 768px.

## Pattern library

### Layout patterns

One page layout (`layout.css`, tokens `aifs.layout.*`):

- **Sheet:** white, edge to edge, no frame, from just under the header. Below it, the footer on the backdrop, revealed as the sheet ends.
- **Content:** On this page in a column on the sheet, then the **fluid content column**: it fills the rest of the row at every window width, with no maximum width (`--sl-content-width` is 100%, in `layout.css`; there is no content-width token). Code, Markdown tables, figures, cards, tabs, steps and the models table use its full width. Its side padding is `aifs.layout.sheet-padding` (40px) from 72rem and `aifs.layout.sheet-padding-wide` (64px) from 120rem; from 80rem it keeps the chat launcher's clearance at its end edge. Card grids and link-card rows fit as many columns of at least `aifs.layout.card-min-width` (320px) as there is room for. Below 72rem On this page is a menu above the content.
- **Measure:** running text stops at `aifs.layout.measure` (45rem, 720px, about 79ch of TeleNeo at 16px): paragraphs, lists, headings (with their anchor link), quotes and asides inside the Markdown content. It stays at the column's start edge, not centred, so it lines up with a table or code block below it. Not capped: tables, code blocks, figures, card grids and link cards, the tab bar, steps (their text stops at the measure, their code does not), the file tree, the banners and the components (models table, plan tiles, featured models, recommended models). Text inside table cells, cards and components keeps their width. A rem value, not `80ch`: DTCG dimensions are px or rem only (GAPS row 21).
- **Vertical rhythm:** one spacing scale on every page, from the `aifs.rhythm.*` tokens on Telekom's 8px scale, set in `layout.css` only; pages and components do not add margins between content blocks. The gap grows with the size of the break:

  | Gap | Token | Value |
  |---|---|---|
  | After a heading, and after the page title | `aifs.rhythm.after-heading` | 12px |
  | Between paragraphs and lists | `aifs.rhythm.flow` | 16px |
  | Around a block: code, table, aside, tabs, card grid or link-card row, steps, component | `aifs.rhythm.block` | 32px |
  | Before an h4 | `aifs.rhythm.heading-4` | 32px |
  | Before an h3 | `aifs.rhythm.heading-3` (`heading-3-compact` below 50rem) | 48px (40px) |
  | Before an h2, or a component that opens a section | `aifs.rhythm.heading-2` (`heading-2-compact` below 50rem) | 72px (48px) |
  | Before previous and next | `aifs.rhythm.page-end` | 96px |

  Block margins collapse with their neighbour's, so a heading after a code block keeps its own gap, not the sum.
- **No breakout band** any more: with a fluid column a wide element (the models table) simply fits the column.
- **Announcement banners** (`PreviewModelsBanner`, a site part): one banner per announcement at the top of the content column, on the sheet, above the title, with the column's edges and width at every window width; no band or backdrop behind them. Each is a region with its own label and has a tag, the text, a link and its own close button. **New**: magenta tag, magenta accent line and a faint magenta tint; **Notice**: standard tag, informational blue accent line and tint, as a note aside. They fade in (opacity only, not with reduced motion) the first time in a session. Each close is remembered for the session on its own; focus moves to the remaining banner's close button, or to the page title after the last. Current pages only; archived pages show none. Tokens: `aifs.notice.*`.
- **Archive bar** (`ArchiveBanner`, a site part): on archived pages (v1.0.0, v1.1.0, v1.2.0) only, the one version notice, in the place of the announcement banners, with the content column's edges and width at every window width. It names the version and links to the same page in the current docs where one exists, and to the home page. starlight-versions' own note under the title is left out (`PageTitle`).
- **Site header** (`SiteHeader`, a site part): the T, the site name and under it the subline "Technical documentation" (German: "Technische Dokumentation"), small and muted; both link to the home page of the page's language. Below 40rem the name is short (AIFS); below 31rem the subline is hidden, as there is no room for it beside the search and the Get API key button. Below 22.5rem (360px) the English button reads "API key", as short as the German "API-Key", so nothing in the header touches; its accessible name stays "Get API key (opens in a new tab)".
- **Site navigation:** every group starts open on every page; the chevrons close a group, and Starlight remembers that for the session. A stored state from before the groups opened by default is dropped once per session (`aifsSidebarDefaultOpen1`, astro.config.mjs).
