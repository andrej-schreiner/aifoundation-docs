AI Foundation Services provides an OpenAI-compatible REST API. All endpoints use the base URL:

```
https://llm-server.ai.t-systems.net/v1
```

For the complete OpenAPI specification, see the [interactive API docs (Redoc)](https://llm-server.llmhub.t-systems.net/redoc).


## Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/models` | List all available models |
| `GET` | `/models/{model_id}` | Get model details and metadata |
| `POST` | `/chat/completions` | Create a chat completion |
| `POST` | `/completions` | Create a text completion |
| `POST` | `/embeddings` | Create embeddings |
| `POST` | `/audio/transcriptions` | Transcribe audio to text |
| `POST` | `/audio/translations` | Translate audio to English |
| `GET` | `/audio/models` | List available audio models |
| `POST` | `/images/generations` | Generate images from text |
| `POST` | `/images/edits` | Edit an image. The [queued-requests section](/guides/reliability#queued-requests) documents this path. |
| `POST` | `/responses` | Create a response (Responses API) |
| `POST` | `/decisions` | Typed decision. See [Decisions](/guides/decisions). |
| `POST` | `/files` | Upload a file |
| `GET` | `/files` | List uploaded files |
| `DELETE` | `/files/{id}` | Delete a file |

Paths above are relative to `https://llm-server.ai.t-systems.net/v1`, so the chat route is `/v1/chat/completions`.

### Queue endpoints

Queue endpoints are served on the previous host, `https://llm-server.llmhub.t-systems.net`. They wait up to two minutes when you are over your rate limit instead of returning `429` immediately. See [Queued requests](/guides/reliability#queued-requests).

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/queue/chat/completions` | Chat completion (queued) |
| `POST` | `/queue/completions` | Text completion (queued) |
| `POST` | `/queue/embeddings` | Embeddings (queued) |
| `POST` | `/queue/audio/transcriptions` | Audio transcription (queued) |
| `POST` | `/queue/audio/translations` | Audio translation (queued) |
| `POST` | `/queue/images/generations` | Image generation (queued) |
| `POST` | `/queue/images/edits` | Image editing (queued) |
| `GET` | `/queue/models` | List models (queue) |


## Hosts

The New API base is `https://llm-server.ai.t-systems.net/v1`. Standard calls use `/v1/...` on that host. A few paths are not on the new host yet and stay on the previous host:

| Host | Used for |
|---|---|
| `https://llm-server.ai.t-systems.net/v1` | Chat, completions, responses, embeddings, audio, images, decisions, files, models |
| `https://llm-server.llmhub.t-systems.net/v2/coding` | Cline, Continue, and OpenCode |
| `https://llm-server.llmhub.t-systems.net/queue` | Queue variants such as `/queue/chat/completions` and `/queue/images/edits` |
| `https://llm-server.llmhub.t-systems.net/v1` | Visual RAG vector stores (`/v1/vector_stores`) on the previous host |

The [Migrate to the new API](/api-transition) page describes moving from the previous endpoint to `https://llm-server.ai.t-systems.net/v1`.


## Authentication

All requests require an API key in the `Authorization` header:

```
Authorization: Bearer YOUR_API_KEY
```

See [Authentication](/getting-started/authentication) for setup details.


## Request format

All POST requests use JSON:

```bash
curl -X POST "https://llm-server.ai.t-systems.net/v1/chat/completions" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-oss-120b", "messages": [{"role": "user", "content": "Hello"}]}'
```


## Response format

Responses follow the OpenAI response format. For chat completions:

```json
{
  "id": "chatcmpl-abc123",
  "object": "chat.completion",
  "created": 1710000000,
  "model": "gpt-oss-120b",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 10,
    "completion_tokens": 9,
    "total_tokens": 19
  }
}
```

:::note[AI-generated content]
Responses that contain model output (chat and text completions, the Responses API, images, audio and decisions) carry the HTTP response header `X-AI-Generated-Content: true`, which marks the content as AI generated in line with the EU AI Act. The response body is unchanged. Embeddings, model listings, file operations and error responses do not carry the header.
:::
