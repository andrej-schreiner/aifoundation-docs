When an API request fails, the response includes an HTTP status code and an error message. Here are the common errors and how to resolve them.

This page describes the API at `https://llm-server.llmhub.t-systems.net/v2`. How codes and the error format differ during the API transition: see [API transition: error handling](/api-transition/#error-handling).


## HTTP status codes

| Code | Name | Description | Resolution |
|---|---|---|---|
| `400` | Bad Request | Invalid request format or parameters, or a model name that can't be resolved | Check your request body, parameters and model name |
| `401` | Unauthorized | Missing or invalid API key | Send your key in the `Authorization: Bearer` header and check that it is correct |
| `402` | Payment Required | Budget exceeded | Don't retry; check your plan's budget or contact support |
| `403` | Forbidden | Key blocked or deactivated, or no access to this model | Check your plan includes the model, or contact support |
| `429` | Too Many Requests | Rate limit exceeded | Wait and retry with exponential backoff |
| `500` | Internal Server Error | Server-side error | Retry after a brief delay |
| `502` | Bad Gateway | The model provider could not be reached | Retry after a brief delay |
| `503` | Service Unavailable | Model is temporarily unavailable | Check [Model Status](https://uptime.llmhub.t-systems.net/status/health) and retry |
| `504` | Gateway Timeout | The model provider did not answer in time | Retry, or send a shorter request |


## Error response format

Errors come back as a structured `error` object:

```json
{
  "error": {
    "message": "Invalid request parameter",
    "type": "invalid_request_error",
    "code": "invalid_value",
    "param": "messages[0].role"
  }
}
```

Use the HTTP status as the primary signal. Treat `type`, `code` and `param` as optional: not every error sets them.


## Handling rate limits (429)

The OpenAI SDKs already retry a `429` twice, with backoff, and follow a `Retry-After` header when one is sent. For service-level rate limits there is no `Retry-After` header. For more retries, wrap the call in your own exponential backoff:

```python
import time
from openai import OpenAI, RateLimitError

client = OpenAI()

def call_with_retry(messages, max_retries=3):
    for attempt in range(max_retries + 1):
        try:
            return client.chat.completions.create(
                model="gpt-oss-120b",
                messages=messages,
            )
        except RateLimitError:
            if attempt == max_retries:
                raise
            wait = 2 ** attempt
            print(f"Rate limited. Retrying in {wait}s...")
            time.sleep(wait)
```

A `402` (budget exceeded) is not a rate limit: don't retry it.


## Common issues

### Model not found (400)
- Verify the model name matches exactly (case-sensitive)
- Use the [List models API](/reference/api-endpoints) to check available models
- If the name is right and you get `403`, your plan doesn't include the model

### Invalid API key (401)
- Ensure the key is correctly set in your environment
- Check that the key hasn't expired
- Visit the [API Key Portal](https://apikey.llmhub.t-systems.net/) to manage keys

### Context length exceeded (400)
- Reduce the input length or set a lower `max_tokens`
- Check the model's `context_length` in the [List models API](/reference/api-endpoints), or its context window in the [catalog](/models/#catalog)
