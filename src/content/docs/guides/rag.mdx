Retrieval-augmented generation here means two calls that already exist: embeddings, then a chat completion that includes the retrieved text. This page does not add a vector database.

:::note[Prerequisites]
- An API key ([get one here](https://apikey.llmhub.t-systems.net/))
- The client from the [quickstart](/)
- An embedding model and a chat model from [Choosing a model](/getting-started/choosing-a-model)
:::

## Minimal example

The embedding call is the one on the [embeddings guide](/guides/embeddings), with `text-embedding-bge-m3` (T-Cloud, context 8K). The chat call uses `gpt-oss-120b`, the quickstart model, also on T-Cloud. The "retrieved" string is text you already have. Nothing in the docs stores it for you.

```python
from openai import OpenAI

client = OpenAI()

passage = "T-Cloud models in this catalog run in Germany."
query = "Where do T-Cloud models run?"

embedded = client.embeddings.create(input=[passage, query], model="text-embedding-bge-m3")
print("vectors:", len(embedded.data))

response = client.chat.completions.create(
    model="gpt-oss-120b",
    messages=[
        {"role": "system", "content": "Answer only from the passage."},
        {"role": "user", "content": f"Passage:\n{passage}\n\nQuestion: {query}"},
    ],
)
print(response.choices[0].message.content)
```

The embeddings guide records this shape of result for the Jina model: an embedding dimension, a vector count, and token usage. It does not record a sample for BGE-M3, so this page does not invent one. The chat call returns message content the same way as the quickstart.

## Parameters

Embeddings: `model` and `input`, as on the embeddings guide. Chat: `model` and `messages`, as on the chat-completions guide.

## Limitations and troubleshooting

The embeddings guide lists two example models and their dimensions: `jina-embeddings-v2-base-de` (768) and `text-embedding-bge-m3` (1024). Qwen3 Embedding 8B is also on T-Cloud; its dimension is not on that page.
