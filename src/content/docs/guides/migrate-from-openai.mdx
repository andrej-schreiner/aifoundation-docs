This page is for an application that already calls OpenAI or Azure OpenAI. It is not the move from the current AIFS endpoint to the New API. That move is [Migrate to the New API](/api-transition).

:::note[Prerequisites]
- An AIFS API key ([get one here](https://apikey.llmhub.t-systems.net/))
- The OpenAI SDK already installed
:::

## Minimal example

The quickstart sets the base URL and sends a chat completion. Keep the SDK. Change the base URL and the key. The model id in that sample is `gpt-oss-120b`.

```bash
export OPENAI_API_KEY="your_api_key_here"
export OPENAI_BASE_URL="https://llm-server.llmhub.t-systems.net/v2"
```

```python
from openai import OpenAI

client = OpenAI()
response = client.chat.completions.create(
    model="gpt-oss-120b",
    messages=[{"role": "user", "content": "Hello from AIFS"}],
)
print(response.choices[0].message.content)
```

The quickstart prints `response.choices[0].message.content`.

## Parameters

`OPENAI_BASE_URL` and `OPENAI_API_KEY` are the two environment variables in the quickstart. The chat body uses `model` and `messages`.

Model ids on AIFS are not the same strings as every OpenAI model id. [Choosing a model](/getting-started/choosing-a-model) lists catalog ids, and [Deprecations](/models/deprecations) names replacements for models that retire on 2026-10-31 or 2026-11-30.

## Limitations and troubleshooting

The docs call the API OpenAI-compatible. They also say that not every parameter exists on every model, and that some models reject the Responses API with HTTP 400. Use the guide for the call you are moving.
