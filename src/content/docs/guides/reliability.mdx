Retry a failed call when the status is temporary. [Error codes](/reference/error-codes) lists every status. [Queued requests](/guides/queued-requests) wait for rate-limit budget instead of returning 429 immediately.

:::note[Prerequisites]
- An API key ([get one here](https://apikey.llmhub.t-systems.net/))
- The client from the [quickstart](/)
:::

## Minimal example

On HTTP 429, wait `2 ** attempt` seconds and try again. Stop after 3 attempts. The model id is `gpt-oss-120b`.

```python
import time
from openai import OpenAI, RateLimitError

client = OpenAI()

def call_with_retry(messages, max_retries=3):
    for attempt in range(max_retries):
        try:
            return client.chat.completions.create(
                model="gpt-oss-120b",
                messages=messages,
            )
        except RateLimitError:
            if attempt == max_retries - 1:
                raise
            wait = 2 ** attempt
            print(f"Rate limited. Retrying in {wait}s...")
            time.sleep(wait)
```

On 429 the function waits and tries again. On the third failure it re-raises the RateLimitError.

## Parameters

`max_retries` is 3. The wait is `2 ** attempt` seconds (1s, then 2s, then 4s).

## Limitations and troubleshooting

- `429` means the rate limit was exceeded. Wait and retry with exponential backoff, or use [queued requests](/guides/queued-requests).
- `500` is a server-side error. Retry after a brief delay.
- `503` means the model is temporarily unavailable. Check [model status](https://uptime.llmhub.t-systems.net/status/health) and retry.
- `400`, `401`, `403`, and `404` are request or credential errors. Retrying the same request will not succeed. See [Error codes](/reference/error-codes).
