When a call fails, the [error codes](/reference/error-codes) page is the list of status codes and the retry example. This page only repeats that guidance. It does not add a new retry policy.

:::note[Prerequisites]
- An API key ([get one here](https://apikey.llmhub.t-systems.net/))
- The client from the [quickstart](/)
:::

## Minimal example

The error-codes page retries HTTP 429 with exponential backoff. The wait is `2 ** attempt` seconds, and the loop stops after 3 attempts. The model id is `gpt-oss-120b`.

```python
import time
from openai import OpenAI, RateLimitError

client = OpenAI()

def call_with_retry(messages, max_retries=3):
    for attempt in range(max_retries):
        try:
            return client.chat.completions.create(
                model="gpt-oss-120b",
                messages=messages,
            )
        except RateLimitError:
            wait = 2 ** attempt
            print(f"Rate limited. Retrying in {wait}s...")
            time.sleep(wait)
    raise Exception("Max retries exceeded")
```

Expected behaviour, from that page: on 429 the function waits and tries again. After 3 failures it raises `Max retries exceeded`.

## Parameters

The loop uses `max_retries=3` and `wait = 2 ** attempt`. No other retry parameter is documented.

## Limitations and troubleshooting

From the error-codes page:

- `429` means the rate limit was exceeded. Wait and retry with exponential backoff, or use [queued requests](/guides/queued-requests), which wait for budget instead of returning 429 immediately.
- `500` is a server-side error. Retry after a brief delay.
- `503` means the model is temporarily unavailable. Check [model status](https://uptime.llmhub.t-systems.net/status/health) and retry.
- `400`, `401`, `403`, and `404` are request or credential errors. Retrying them unchanged will not succeed. The resolutions are on the error-codes page.
