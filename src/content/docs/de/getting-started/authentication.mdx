AI Foundation Services verwendet API-Schlüssel zur Authentifizierung. Alle Anfragen müssen Ihren API-Schlüssel im `Authorization`-Header enthalten.


## API-Schlüssel erhalten

### Kostenloser Test-Schlüssel

Starten Sie sofort mit einem kostenlosen Test-Schlüssel:

1. Besuchen Sie das [API-Schlüssel-Portal](https://apikey.llmhub.t-systems.net/)
2. Erstellen Sie ein Konto und generieren Sie Ihren API-Schlüssel
3. Ihr Test-Schlüssel schaltet alle Modelle frei, einschließlich Premium-Modelle

### Produktions-Schlüssel

Für produktive Workloads [kontaktieren Sie uns](mailto:ai@t-systems.com).


## Umgebungsvariablen einrichten

Speichern Sie Ihren API-Schlüssel als Umgebungsvariable — schreiben Sie ihn niemals direkt in Ihren Quellcode.

<Tabs>
  <TabItem value="mac" label="macOS/Linux" default>
    ```bash
    export OPENAI_API_KEY="your_api_key_here"
    export OPENAI_BASE_URL="https://llm-server.ai.t-systems.net/v1"
    ```

    Um die Variablen sitzungsübergreifend zu speichern, fügen Sie diese Zeilen zu Ihrer `~/.zshrc`- oder `~/.bashrc`-Datei hinzu.
  </TabItem>
  <TabItem value="windows-ps" label="PowerShell">
    ```powershell
    $env:OPENAI_API_KEY = "your_api_key_here"
    $env:OPENAI_BASE_URL = "https://llm-server.ai.t-systems.net/v1"
    ```
  </TabItem>
  <TabItem value="windows-cmd" label="CMD">
    ```bash
    setx OPENAI_API_KEY "your_api_key_here"
    setx OPENAI_BASE_URL "https://llm-server.ai.t-systems.net/v1"
    ```
  </TabItem>
</Tabs>


## API-Schlüssel verwenden

### Mit OpenAI-SDKs

Wenn `OPENAI_API_KEY` und `OPENAI_BASE_URL` gesetzt sind, werden sie von den OpenAI-SDKs automatisch übernommen:

```python
from openai import OpenAI

client = OpenAI()  # No need to pass api_key or base_url
```

Sie können sie auch explizit übergeben:

```python
from openai import OpenAI

client = OpenAI(
    api_key="your_api_key_here",
    base_url="https://llm-server.ai.t-systems.net/v1",
)
```

### Mit HTTP-Anfragen

Fügen Sie den API-Schlüssel im `Authorization`-Header ein:

```bash
curl -X POST "https://llm-server.ai.t-systems.net/v1/chat/completions" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-oss-120b", "messages": [{"role": "user", "content": "Hello"}]}'
```


## Basis-URL

Alle API-Anfragen gehen an:

```
https://llm-server.ai.t-systems.net/v1
```

Dies ist der OpenAI-kompatible Endpunkt. Die vollständige API-Spezifikation finden Sie in der [API-Referenz](https://llm-server.llmhub.t-systems.net/redoc).


## Empfohlene Praxis

- **API-Schlüssel niemals committen** — verwenden Sie `.env`-Dateien und fügen Sie diese zur `.gitignore` hinzu.
- **Umgebungsvariablen verwenden** — in der Produktion statt fest eingecodeter Schlüssel.
- **Schlüssel regelmäßig rotieren** über das [API-Schlüssel-Portal](https://apikey.llmhub.t-systems.net/).
- **Nutzung überwachen** über das API-Schlüssel-Portal, um Token-Verbrauch und Kosten zu verfolgen.
