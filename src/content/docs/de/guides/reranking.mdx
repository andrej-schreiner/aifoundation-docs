Ein Reranker bewertet, wie gut jedes Dokument eine Anfrage beantwortet, und gibt die Dokumente nach dieser Bewertung sortiert zurück. Setzen Sie ihn als zweiten Schritt einer Such- oder RAG-Pipeline ein: Holen Sie zuerst schnell 20 bis 100 Kandidaten mit [Embeddings](/de/guides/embeddings) oder einer Stichwortsuche, und lassen Sie dann den Reranker die wenigen auswählen, die die Frage wirklich beantworten, bevor Sie sie an ein Chat-Modell übergeben.

Der Reranker liest die Anfrage und jedes Dokument gemeinsam. Er erkennt so Relevanz, die der Embedding-Ähnlichkeit entgeht, braucht dafür aber einen Modellaufruf pro Paar aus Anfrage und Dokument.

:::note[Voraussetzungen]
- Ein API-Schlüssel ([hier erhalten](https://apikey.llmhub.t-systems.net/))
- `OPENAI_API_KEY` und `OPENAI_BASE_URL` gesetzt wie im [Quickstart](/de/getting-started/quickstart)
:::

**Was Sie lernen werden:**
- Wie Sie Dokumente mit curl, Python und Node.js neu sortieren
- Wie Sie den Endpunkt mit dem Cohere SDK aufrufen
- Wie Sie Reranking in eine Pipeline aus Suche und Generierung einbauen

## Grundlegende Verwendung

Senden Sie eine `query` und eine Liste von `documents`. Die Antwort listet die Dokumente vom relevantesten zum am wenigsten relevanten, jeweils mit seiner Position in Ihrer Liste (`index`) und einem `relevance_score` zwischen 0 und 1.

### Anfrageparameter

| Parameter | Typ | Beschreibung |
|---|---|---|
| `model` | String | `Qwen3-Reranker-4B` |
| `query` | String | Die Suchanfrage oder Frage |
| `documents` | Array von Strings | Die zu bewertenden Kandidaten. Senden Sie mindestens einen |
| `top_n` | Integer | Optional. Gibt nur die besten `n` Dokumente zurück. Lassen Sie es weg oder senden Sie `0`, um alle zu erhalten |
| `truncate_prompt_tokens` | Integer | Optional. Kürzt jedes Paar aus Anfrage und Dokument auf diese Anzahl Tokens, für lange Dokumente (siehe [Tipps und Grenzen](#tipps-und-grenzen)) |


## Mit dem Cohere SDK

Der Endpunkt ist kompatibel mit den Rerank-APIs von Cohere und Jina, das Cohere SDK funktioniert also ohne Anpassungen. `cohere.ClientV2` ruft `/v2/rerank` auf und `cohere.Client` ruft `/v1/rerank` auf; beide hängen den Pfad selbst an, übergeben Sie die Basis-URL daher **ohne** `/v2`.

```python showLineNumbers
import os

import cohere

# The Cohere SDK adds /v2/rerank itself, so pass the base URL without /v2.
co = cohere.ClientV2(
    api_key=os.environ["OPENAI_API_KEY"],
    base_url=os.environ["OPENAI_BASE_URL"].removesuffix("/v2"),
)

response = co.rerank(
    model="Qwen3-Reranker-4B",
    query="What is the capital of Germany?",
    documents=[
        "Paris is the capital of France.",
        "Berlin is the capital and largest city of Germany.",
        "Bananas are rich in potassium.",
    ],
    top_n=2,
)

for result in response.results:
    print(f"{result.relevance_score:.4f}  [{result.index}]")
```

Andere Tools, die einen Cohere- oder Jina-kompatiblen Rerank-Endpunkt unterstützen, können dasselbe Modell nutzen: Richten Sie sie auf `https://llm-server.llmhub.t-systems.net/v2/rerank` mit Ihrem API-Schlüssel aus.


## Erst suchen, dann neu sortieren

Eine typische RAG-Pipeline erstellt ein Embedding der Anfrage, behält die nächstgelegenen Kandidaten und sortiert sie neu, sodass nur die relevantesten beim Chat-Modell ankommen. Dieses Beispiel nutzt [Qwen3 Embedding 8B](/de/guides/embeddings) für die Suche (`pip install openai numpy`).

```python showLineNumbers
import numpy as np
from openai import OpenAI

client = OpenAI()

query = "How many vacation days do part-time employees get?"
documents = [
    "Full-time employees receive 30 vacation days per calendar year.",
    "Part-time employees receive vacation days in proportion to their working days per week.",
    "Vacation requests must be submitted in the HR portal at least two weeks in advance.",
    "The canteen is open from 11:30 to 14:00 on working days.",
    "Employees working four days a week receive 24 vacation days per year.",
    "Sick days do not count as vacation days if a doctor's note is submitted.",
]

# 1. Retrieve: embed the query and the documents, keep the closest candidates.
emb = client.embeddings.create(model="qwen3-embedding-8b", input=[query] + documents)
vectors = np.array([d.embedding for d in emb.data])
vectors /= np.linalg.norm(vectors, axis=1, keepdims=True)
similarity = vectors[1:] @ vectors[0]
candidates = [documents[i] for i in np.argsort(-similarity)[:4]]

# 2. Rerank: score each candidate against the query, keep the best two.
reranked = client.post(
    "/rerank",
    body={"model": "Qwen3-Reranker-4B", "query": query, "documents": candidates, "top_n": 2},
    cast_to=object,
)
for r in reranked["results"]:
    print(f"{r['relevance_score']:.4f}  {r['document']['text']}")

# 3. Pass these documents to your chat model as context.
context = [r["document"]["text"] for r in reranked["results"]]
```

**Beispielausgabe:**
```
0.9972  Part-time employees receive vacation days in proportion to their working days per week.
0.9938  Employees working four days a week receive 24 vacation days per year.
```

In der Produktion speichern Sie die Embeddings der Dokumente in einem Vector Store, statt sie bei jeder Anfrage neu zu berechnen.


## Tipps und Grenzen

- **Jedes Dokument wird abgerechnet, auch mit `top_n`.** `top_n` kürzt nur die Antwort. Jedes Paar aus Anfrage und Dokument ist eine eigene Modelleingabe: die Anfrage, das Dokument und etwa 70 Tokens Prompt-Vorlage des Modells. Sortieren Sie einige Dutzend Kandidaten neu, nicht Ihren ganzen Bestand.
- **Scores dienen der Reihenfolge.** Sie sind innerhalb einer Anfrage vergleichbar. Wenn Sie nach einem Schwellenwert filtern, wählen Sie ihn anhand Ihrer eigenen Daten.
- **Lange Dokumente werden gekürzt, nicht abgelehnt.** Ein Paar, das länger ist als das Kontextfenster, wird gekürzt und nur der Teil bewertet, der hineinpasst. Senden Sie `truncate_prompt_tokens` (zum Beispiel 4096), um lange Paare früher und schneller zu kürzen, oder teilen Sie lange Dokumente in Abschnitte.
- **Viele Dokumente pro Anfrage sind kein Problem.** 100 Dokumente kommen in unter zwei Sekunden zurück, 500 in etwa drei.
- **Dokumente kommen immer mit zurück.** Jedes Ergebnis enthält `document.text`; der Cohere-Parameter `return_documents` wird ignoriert.
- **Keine Queue-Variante.** `/queue/rerank` gibt es nicht; wiederholen Sie die Anfrage stattdessen bei `429`.
