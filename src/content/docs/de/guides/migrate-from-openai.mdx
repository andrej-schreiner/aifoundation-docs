Stellen Sie eine Anwendung, die bereits OpenAI oder Azure OpenAI aufruft, auf AI Foundation Services um. Das SDK bleibt. Basis-URL, API-Schlüssel und Modell-ID ändern sich.

Der Wechsel vom heutigen AIFS-Endpunkt zur neuen API ist eine eigene Anleitung: [Umstieg auf die neue API](/de/api-transition).

:::note[Voraussetzungen]
- Ein AIFS-API-Schlüssel ([hier erhalten](https://apikey.llmhub.t-systems.net/))
- Das OpenAI SDK ist bereits installiert
:::

## Minimales Beispiel

```bash
export OPENAI_API_KEY="your_api_key_here"
export OPENAI_BASE_URL="https://llm-server.llmhub.t-systems.net/v2"
```

```python
from openai import OpenAI

client = OpenAI()
response = client.chat.completions.create(
    model="gpt-oss-120b",
    messages=[{"role": "user", "content": "Hello from AIFS"}],
)
print(response.choices[0].message.content)
```

Der Antworttext steht in `response.choices[0].message.content`.

## Parameter

Setzen Sie `OPENAI_BASE_URL` und `OPENAI_API_KEY`. Der Chat-Körper nutzt `model` und `messages`.

Modell-IDs auf AIFS unterscheiden sich von OpenAI-Modell-IDs. [Modell wählen](/de/getting-started/choosing-a-model) listet den Katalog. [Abkündigungen](/de/models/deprecations) listet Stilllegungsdaten und Ersatzmodelle.

## Grenzen und Fehlersuche

Die API ist OpenAI-kompatibel. Nicht jeder Parameter existiert auf jedem Modell. Einige Modelle antworten auf die Responses API mit HTTP 400. Nutzen Sie die Anleitung für den Aufruf, den Sie migrieren.
