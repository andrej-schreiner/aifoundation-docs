Diese Seite ist für eine Anwendung, die bereits OpenAI oder Azure OpenAI aufruft. Sie ist nicht der Wechsel vom heutigen AIFS-Endpunkt zur neuen API. Dieser Wechsel ist [Umstieg auf die neue API](/de/api-transition).

:::note[Voraussetzungen]
- Ein AIFS-API-Schlüssel ([hier erhalten](https://apikey.llmhub.t-systems.net/))
- Das OpenAI SDK ist bereits installiert
:::

## Minimales Beispiel

Der Quickstart setzt die Basis-URL und sendet eine Chat Completion. Das SDK bleibt. Basis-URL und Schlüssel ändern sich. Die Modell-ID in diesem Beispiel ist `gpt-oss-120b`.

```bash
export OPENAI_API_KEY="your_api_key_here"
export OPENAI_BASE_URL="https://llm-server.llmhub.t-systems.net/v2"
```

```python
from openai import OpenAI

client = OpenAI()
response = client.chat.completions.create(
    model="gpt-oss-120b",
    messages=[{"role": "user", "content": "Hello from AIFS"}],
)
print(response.choices[0].message.content)
```

Der Quickstart gibt `response.choices[0].message.content` aus.

## Parameter

`OPENAI_BASE_URL` und `OPENAI_API_KEY` sind die beiden Umgebungsvariablen im Quickstart. Der Chat-Körper nutzt `model` und `messages`.

Modell-IDs auf AIFS sind nicht dieselben Zeichenketten wie jede OpenAI-Modell-ID. [Modell wählen](/de/getting-started/choosing-a-model) listet Katalog-IDs, und [Abkündigungen](/de/models/deprecations) nennt Ersatz für Modelle, die am 31.10.2026 oder 30.11.2026 stillgelegt werden.

## Grenzen und Fehlersuche

Die Dokumente nennen die API OpenAI-kompatibel. Sie sagen auch, dass nicht jeder Parameter auf jedem Modell existiert und dass einige Modelle die Responses API mit HTTP 400 ablehnen. Nutzen Sie die Anleitung für den Aufruf, den Sie verschieben.
