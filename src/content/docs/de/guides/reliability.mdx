Wiederholen Sie einen fehlgeschlagenen Aufruf, wenn der Status vorübergehend ist. [Fehlercodes](/de/reference/error-codes) listet jeden Status. [Queued Requests](#queued-requests) warten auf Rate-Limit-Budget, statt sofort 429 zu liefern.

:::note[Voraussetzungen]
- Ein API-Schlüssel ([hier erhalten](https://apikey.llmhub.t-systems.net/))
- Der Client aus dem [Quickstart](/de/)
:::

## Minimales Beispiel

Bei HTTP 429 warten Sie `2 ** attempt` Sekunden und versuchen es erneut. Nach 3 Versuchen bricht die Schleife ab. Die Modell-ID ist `gpt-oss-120b`.

```python
import time
from openai import OpenAI, RateLimitError

client = OpenAI()

def call_with_retry(messages, max_retries=3):
    for attempt in range(max_retries):
        try:
            return client.chat.completions.create(
                model="gpt-oss-120b",
                messages=messages,
            )
        except RateLimitError:
            if attempt == max_retries - 1:
                raise
            wait = 2 ** attempt
            print(f"Rate limited. Retrying in {wait}s...")
            time.sleep(wait)
```

Bei 429 wartet die Funktion und versucht es erneut. Beim dritten Fehlschlag wirft sie den RateLimitError erneut.

## Parameter

`max_retries` ist 3. Die Wartezeit ist `2 ** attempt` Sekunden (1 s, dann 2 s, dann 4 s).

## Grenzen und Fehlersuche

- `429` bedeutet, das Rate-Limit ist erreicht. Warten und mit exponentiellem Backoff wiederholen, oder [Queued Requests](#queued-requests) nutzen.
- `500` ist ein serverseitiger Fehler. Nach kurzer Pause erneut versuchen.
- `503` bedeutet, das Modell ist vorübergehend nicht verfügbar. [Modellstatus](https://uptime.llmhub.t-systems.net/status/health) prüfen und erneut versuchen.
- `400`, `401`, `403` und `404` sind Fehler der Anfrage oder der Zugangsdaten. Dieselbe Anfrage erneut zu senden hilft nicht. Siehe [Fehlercodes](/de/reference/error-codes).

Die Obergrenze der Queue-Wartezeit ist die Stelle, an der diese Doku `Retry-After` festlegt. Siehe [Queued Requests](#queued-requests).

## Queued Requests

Die `/queue`-Endpunkte funktionieren wie die `/v2`-Endpunkte, mit einem Unterschied: Wenn Sie Ihr [Rate-Limit](/de/reference/rate-limits) überschreiten, antwortet `/v2` sofort mit `429 Too Many Requests`, während `/queue` bis zu zwei Minuten wartet, bis Ihr Limit wieder frei ist, und die Anfrage dann ausführt.

:::caution
`/queue` ist nicht asynchron. Es gibt keine Job-ID und nichts abzufragen: Sie erhalten die Antwort auf derselben Verbindung wie bei `/v2`. Anfragen werden dadurch weder schneller noch verlängern sich ihre Timeouts.
:::

:::note[Voraussetzungen]
- Ein API-Schlüssel ([hier erhalten](https://apikey.llmhub.t-systems.net/))
- OpenAI SDK oder HTTP-Client installiert ([Quickstart](/de/))
:::


## So funktioniert es

- **Innerhalb Ihres Limits:** Die Anfrage wird sofort ausgeführt.
- **Über Ihrem Limit:** Die Anfrage wartet. Limits werden jede Minute zurückgesetzt, daher wird sie zu Beginn jeder Minute erneut geprüft.
- **Nach zwei Minuten noch über Ihrem Limit:** Die Wartezeit ist begrenzt. Die Anfrage wartet nicht länger, und Sie erhalten `429 Too Many Requests` mit einem `Retry-After`-Header, der angibt, nach wie vielen Sekunden Sie es erneut versuchen können. Der Body enthält `Queue wait limit of 120 seconds reached`. Diese Obergrenze sorgt dafür, dass ein ausgehungertes Projekt eine klare Antwort erhält statt eines undurchsichtigen `504 Gateway Timeout` aus der Netzwerkschicht.

Die Obergrenze richtet sich nach der [Kalenderminute](/de/reference/rate-limits#wie-das-minutenfenster-gezählt-wird), nicht nach dem Zeitpunkt, zu dem Ihre Anfrage eintrifft: Die Anfrage wird beim Eintreffen geprüft und erneut bei den nächsten beiden Minutenwechseln; nach dem zweiten gibt sie auf. Die tatsächliche Wartezeit liegt daher zwischen einer und zwei Minuten, je nachdem, wann innerhalb der Minute Sie die Anfrage gesendet haben.

Stellen Sie das Client-Timeout auf mindestens zwei Minuten plus die erwartete Antwortzeit ein, sonst gibt Ihr Client möglicherweise auf, bevor die Queue es tut. Wenn Sie die Verbindung während des Wartens schließen, wird die Anfrage abgebrochen.

Ein `429` von `/queue` bedeutet, dass Sie dauerhaft mehr senden, als Ihr Limit erlaubt, nicht nur eine kurze Spitze. Eine einzelne Anfrage mit mehr Input-Tokens als Ihr Token-Limit pro Minute passt nie und läuft daher immer nach zwei Minuten in den Timeout. Senden Sie langsamer oder [beantragen Sie ein höheres Limit](/de/reference/rate-limits).


## Wann die Queue API verwenden

- **Verwenden Sie `/queue`** für Batch-Jobs, die gelegentlich über dem Limit liegen, damit kurze Spitzen warten statt fehlzuschlagen.
- **Verwenden Sie `/v2`** für interaktive Anwendungen, bei denen ein sofortiger `429` besser ist als Warten, und für lang laufende Anfragen (nutzen Sie [Streaming](/de/guides/streaming)).


## Endpunkt-Zuordnung

Jeder Standard-Endpunkt hat ein `/queue`-Aequivalent:

| Standard-Endpunkt | Queue-Endpunkt | Beschreibung |
|---|---|---|
| `POST /v2/chat/completions` | `POST /queue/chat/completions` | Chat Completion |
| `POST /v2/completions` | `POST /queue/completions` | Text Completion |
| `POST /v2/embeddings` | `POST /queue/embeddings` | Embeddings |
| `POST /v2/audio/transcriptions` | `POST /queue/audio/transcriptions` | Audio Transcription |
| `POST /v2/audio/translations` | `POST /queue/audio/translations` | Audio Translation |
| `POST /v2/images/generations` | `POST /queue/images/generations` | Image Generation |
| `POST /v2/images/edits` | `POST /queue/images/edits` | Image Edit |
| `GET /v2/models` | `GET /queue/models` | Modelle auflisten |

Der Request-Body fuer jeden Queue-Endpunkt ist **identisch** mit seinem Standard-Gegenstueck — aendern Sie einfach den Basispfad von `/v2` zu `/queue`.

## Beispiel fuer Batch-Verarbeitung

Verarbeiten Sie mehrere Prompts effizient ueber die Warteschlange:

<Tabs>
  <TabItem value="python" label="Python" default>

```python

from openai import AsyncOpenAI

client = AsyncOpenAI(
    base_url="https://llm-server.llmhub.t-systems.net/queue",
)

prompts = [
    "Summarize the benefits of solar energy.",
    "Explain how wind turbines generate electricity.",
    "Describe the future of hydrogen fuel cells.",
]

async def process_prompt(prompt):
    response = await client.chat.completions.create(
        model="gpt-oss-120b",
        messages=[{"role": "user", "content": prompt}],
        max_tokens=500,
    )
    return response.choices[0].message.content

async def main():
    tasks = [process_prompt(p) for p in prompts]
    results = await asyncio.gather(*tasks)
    for prompt, result in zip(prompts, results):
        print(f"Prompt: {prompt[:50]}...")
        print(f"Result: {result[:100]}...\n")

asyncio.run(main())
```

  </TabItem>
  <TabItem value="node" label="Node.js">

```javascript

const client = new OpenAI({
  baseURL: "https://llm-server.llmhub.t-systems.net/queue",
```

## Queue-Endpunkte fuer andere APIs

### Embeddings

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://llm-server.llmhub.t-systems.net/queue",
)

response = client.embeddings.create(
    model="text-embedding-bge-m3",
    input="The benefits of renewable energy in Europe",
)

print(f"Embedding dimension: {len(response.data[0].embedding)}")
```

### Audio Transcription

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://llm-server.llmhub.t-systems.net/queue",
)

with open("meeting_recording.mp3", "rb") as audio_file:
    transcript = client.audio.transcriptions.create(
        model="whisper-large-v3",
        file=audio_file,
    )

print(transcript.text)
```

### Image Generation

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://llm-server.llmhub.t-systems.net/queue",
)

result = client.images.generate(
    model="gpt-image-2",
    prompt="A futuristic data center powered by renewable energy",
)

print(result.data[0].b64_json[:50] + "...")
```
