Wenn eine API-Anfrage fehlschlägt, enthält die Antwort einen HTTP-Statuscode und eine Fehlermeldung. Hier finden Sie die häufigsten Fehler und deren Behebung.

Diese Seite beschreibt die API unter `https://llm-server.llmhub.t-systems.net/v2`. Wie sich Codes und Fehlerformat während der API-Umstellung unterscheiden, lesen Sie unter [API-Umstellung: Fehlerbehandlung](/de/api-transition/#fehlerbehandlung).


## HTTP-Statuscodes

| Code | Name | Beschreibung | Lösung |
|---|---|---|---|
| `400` | Bad Request | Ungültiges Anfrageformat oder ungültige Parameter, oder ein Modellname, der sich nicht auflösen lässt | Prüfen Sie den Anfragekörper, die Parameter und den Modellnamen |
| `401` | Unauthorized | Fehlender oder ungültiger API-Schlüssel | Senden Sie Ihren Schlüssel im `Authorization: Bearer`-Header und prüfen Sie, ob er stimmt |
| `402` | Payment Required | Budget überschritten | Nicht wiederholen; prüfen Sie das Budget Ihres Tarifs oder kontaktieren Sie den Support |
| `403` | Forbidden | Schlüssel gesperrt oder deaktiviert, oder kein Zugriff auf dieses Modell | Prüfen Sie, ob Ihr Tarif das Modell enthält, oder kontaktieren Sie den Support |
| `429` | Too Many Requests | Rate-Limit überschritten | Warten und mit exponentiellem Backoff erneut versuchen |
| `500` | Internal Server Error | Serverseitiger Fehler | Nach kurzer Verzögerung erneut versuchen |
| `502` | Bad Gateway | Der Modellanbieter ist nicht erreichbar | Nach kurzer Verzögerung erneut versuchen |
| `503` | Service Unavailable | Modell ist vorübergehend nicht verfügbar | [Modellstatus](https://uptime.llmhub.t-systems.net/status/health) prüfen und erneut versuchen |
| `504` | Gateway Timeout | Der Modellanbieter hat nicht rechtzeitig geantwortet | Erneut versuchen oder eine kürzere Anfrage senden |


## Fehlerantwort-Format

Fehler kommen als strukturiertes `error`-Objekt zurück:

```json
{
  "error": {
    "message": "Invalid request parameter",
    "type": "invalid_request_error",
    "code": "invalid_value",
    "param": "messages[0].role"
  }
}
```

Werten Sie in erster Linie den HTTP-Status aus. `type`, `code` und `param` sind optional: Nicht jeder Fehler setzt sie.


## Umgang mit Rate-Limits (429)

Die OpenAI-SDKs wiederholen ein `429` bereits zweimal mit Backoff und beachten einen `Retry-After`-Header, wenn einer gesendet wird. Bei Rate-Limits auf Service-Ebene gibt es keinen `Retry-After`-Header. Für mehr Wiederholungen umschließen Sie den Aufruf mit einem eigenen exponentiellen Backoff:

```python
import time
from openai import OpenAI, RateLimitError

client = OpenAI()

def call_with_retry(messages, max_retries=3):
    for attempt in range(max_retries + 1):
        try:
            return client.chat.completions.create(
                model="gpt-oss-120b",
                messages=messages,
            )
        except RateLimitError:
            if attempt == max_retries:
                raise
            wait = 2 ** attempt
            print(f"Rate limited. Retrying in {wait}s...")
            time.sleep(wait)
```

Ein `402` (Budget überschritten) ist kein Rate-Limit: Wiederholen Sie die Anfrage nicht.


## Häufige Probleme

### Modell nicht gefunden (400)
- Prüfen Sie, ob der Modellname exakt übereinstimmt (Groß-/Kleinschreibung beachten)
- Verwenden Sie die [Modelle-API](/de/reference/api-endpoints), um verfügbare Modelle zu prüfen
- Ist der Name richtig und Sie erhalten `403`, enthält Ihr Tarif das Modell nicht

### Ungültiger API-Schlüssel (401)
- Stellen Sie sicher, dass der Schlüssel korrekt in Ihrer Umgebung gesetzt ist
- Prüfen Sie, ob der Schlüssel abgelaufen ist
- Besuchen Sie das [API-Schlüssel-Portal](https://apikey.llmhub.t-systems.net/), um Schlüssel zu verwalten

### Kontextlänge überschritten (400)
- Kürzen Sie die Eingabe oder setzen Sie einen niedrigeren Wert für `max_tokens`
- Prüfen Sie `context_length` des Modells in der [Modelle-API](/de/reference/api-endpoints) oder sein Kontextfenster im [Katalog](/de/models/#katalog)
